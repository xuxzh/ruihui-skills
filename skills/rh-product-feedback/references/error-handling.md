# 错误分类与恢复

判断依据是**实际返回**，不是工具描述，也不是「保存成功」这类文案。

技能只走一条通道：随包入口脚本 `scripts/zentao.mjs` 调官方禅道 CLI。CLI 失败时 `stderr` 是 `{"ok":false,"error":{"code":"1004","message":"…"}}`、退出码非 0；入口脚本把它转成一句人话（`错误：禅道 CLI 报错（1004）：<原因>`）、stdout 打一行 `{"ok":false,…}`，**不回显站点地址与凭据**。

下面按**四类**分流。错误码表以 CLI 为准（`E####` 是文本输出的写法，JSON 里是裸数字 `####`；完整表见 [zentao-cli.md](zentao-cli.md)「错误码」），每类对应一种用户能懂的下一步。

## 一、认证类：E1001 / E1003 / E1004 / E1006

| 码 | 含义 | 下一步 |
| --- | --- | --- |
| `E1001` | 环境凭据不全：站点地址、账号、令牌或密码三者没凑齐（`details.reason = "incomplete_environment"` 表示只给了一部分） | 让终端用户**自己**在本机重写接入凭据（`bash <技能目录>/scripts/set-credentials.sh`，Windows 用 `set-credentials.ps1`），写完跑一次自检 |
| `E1003` | 用户名或密码不对 | 同上：核对后在本人终端重写一次；**不在对话里索要密码**，也不替他试 |
| `E1004` | 令牌失效（也对应 HTTP 401） | 令牌是每次运行现换的，所以这条多半是凭据本身不行：重跑一次命令（会换新令牌），仍报错就让用户重写凭据；写命令遇到 401 说明请求没被执行，重跑不会造重复单 |
| `E1006` | 没有可用凭据（凭据文件不存在或内容不完整） | 让用户跑一次写入凭据的命令；不猜、不代填、不用默认账号顶替 |

要点：

- **凭据必须由本人输入**：Agent 不代劳、不索要、不回显；写完让用户说一句「验证一下禅道连接」，跑 `products` 确认生效。
- **连续失败可能触发禅道锁号**：不反复重试。两次失败就停下，如实说「你的禅道账号可能被锁定了，去禅道解锁后我再来」。
- 排错信息里也不带账号、密码、令牌：不打印、不贴进回复。

## 二、参数与版本类：E2003 / E2004 / E2007 / E2009 / E2010 / E2011 / E2012

| 码 | 含义 | 下一步 |
| --- | --- | --- |
| `E2003` | 缺少必填参数 | 回 [zentao-cli.md](zentao-cli.md)「字段」核对载荷的请求体，补齐后再发一次——这条请求没被执行，重试安全 |
| `E2004` | 参数值无效（类型、范围、枚举） | 同上；产品 ID 与单据 ID 写整数，`severity` / `pri` 用数字，枚举按文档写 |
| `E2007` | `--data` 的 JSON 无效（不是对象，或 `@-` 没拿到输入） | 载荷文件里放**一个 JSON 对象**、就是请求体本身，不要再套一层 `payload` |
| `E2009` | 选项值无效：未知选项、同名旗标与 `--data` 冲突、非法枚举、`@文件` 读不到 | 回文档核对子命令与它认的选项（`node <技能目录>/scripts/zentao.mjs --help`）；正文只走 `--payload-file` |
| `E2010` | 当前禅道版本不支持这个动作（`minVersion` 不够） | 说清「**这台禅道不支持这个动作**」，然后**改用语义等价的做法**（例：改不了就追加一条补充说明，或让用户走禅道网页端），别当成权限问题 |
| `E2011` | 认不出禅道版本（只接受 `biz` / `max` / `ipd` + 点分数字） | 服务器版本串异常，交管理员核对实例版本 |
| `E2012` | 认不出站点配置（站点根地址的 `?mode=getconfig` 没返回含 `version` 的 JSON） | 地址可能指到了代理或错误站点：请管理员核对 `config.local.json` 的 `zentaoWebUrl` |

要点：**参数类重试安全**（请求没执行），**版本类重试无意义**（同一个动作还是不支持）。两类都要回随包文档（[zentao-cli.md](zentao-cli.md)、[setup.md](setup.md)）核对命令与字段，不靠猜。

## 三、网络类：E1002 / E5001 / E5002

| 码 | 含义 | 下一步 |
| --- | --- | --- |
| `E1002` | 禅道地址不可达（DNS、网络、VPN、端口） | 核对地址与网络/VPN；地址只从 `config.local.json` 读，不主动回显 |
| `E5001` | 请求超时 | **读**命令可以重跑（必要时加 `--timeout <毫秒>`）；**写**命令一律先按「结果不确定」核实，不重发 |
| `E5002` | SSL/TLS 证书校验失败 | 先确认地址对不对；确实是自签证书才提 `--insecure`，并说清风险（凭据会发给一个没验证过的对端） |

要点：**只有证书问题才提 `--insecure`**；别的网络错误不动证书开关，也不改技能包里的地址。`--timeout` 与 `--insecure` 是**所有子命令都能带**的全局旗标，入口脚本原样转给官方禅道 CLI（`--timeout` 不是入口脚本等 CLI 子进程的超时，两者不是一回事）。

## 四、结果不明类：E2002 / E2006 / E2008 / E5003 与「写入结果不明」

| 码 / 现象 | 含义 | 下一步 |
| --- | --- | --- |
| `E2002` | 找不到对象（也对应 HTTP 404） | 编号或 URL 不对：先按标题或产品重新查一次，把候选列给用户挑，别按错误的 ID 重试写 |
| `E2006` | 当前账号没有权限（也对应 HTTP 403） | 如实说「你的账号看不到 / 没权限」，请用户找管理员开权限；**不绕过禅道权限** |
| `E2008` | 服务端返回错误（也用于分页异常） | 读服务端给的原因；读命令遇到分页不前进会退回「只读第 1 页」并把覆盖范围标成不完整（见 [zentao-cli.md](zentao-cli.md)「已知限制」与 issue #25） |
| `E5003` | 请求被取消（超时中断） | 取消不回滚写入：按「结果不确定」先查后报 |
| 写入结果不明 | 超时、断连、响应看不懂；或返回成功但回读对不上 | **先查询核实，不重发**（见下节） |

要点：

- **先查后报，不重发**：禅道创建没有幂等键，重发会造两条记录。
- **「没查到」≠「没创建」**：不把没查到说成没创建，也不把「保存成功」当成落库证据。
- 权限类如实说「你的账号看不到」，不暗示「对象不存在」。

## 结果不确定：先查后报

创建类调用出现超时、断连、返回解析失败时，**同一份内容不重复创建**（禅道创建接口没有幂等键，重复提交会产生两条记录）。

**没有可解析的业务状态 = 结果不确定**：响应看不懂、既不是成功封装也不是错误封装时，禅道到底有没有写入无从得知——一律按结果不确定处理，先查后报。参数错误（`E2003` / `E2004` / `E2007` / `E2009`）除外：那是请求没被执行，按失败处理。

处理顺序：

1. **留基线**：写入前那次查重扫描就是基线——记下当时扫到的单据 ID。基线之外的 ID 才可能是本次新建；基线里已有的同名单据不是。
2. **查**：用入口脚本重新扫描该产品（`feedbacks --product <产品ID>` / `bugs --product <产品ID>`），并确认这次扫描是**完整的**：没读失败、没分页不前进的提示、没到条数上限。扫描不完整就按「未确认」处理。
3. **判**：候选 = 基线里没有的 ID，且回读后产品、标题、完整描述（换行归一化后逐字比较）都与本次草稿一致，并且有 `opened` 流水。
   - 恰好一条 → 按已创建交付，取它的 ID 做回读校验，并说明「创建请求没拿到确认，是查询核实到的」。
   - 多条 → 报**无法唯一确认**：把候选 ID 列给用户去禅道核对，不替用户挑一条。
   - 零条 → 报**未确认**：「复查没找到本次写入的新记录，但也不能断定禅道没写进去」。让用户决定是否重新提交——第二次创建由用户发起，不自动重试。
   - 扫描不完整 → 报**未确认**，说明复查不完整、结论不成立。
4. **回读**：无论哪条路径，最终都用入口脚本 `feedback --id <ID>` / `bug --id <ID>` 核对标题与描述。

「没查到」只能说明没查到，不能说成「没创建」——查询失败或扫描不完整时尤其如此。

## 补充说明：写前复核与本次流水

禅道的更新接口是**无条件覆盖**，没有版本号 CAS：别人先改过同一条单据，你的写入会盖掉对方的内容。

1. **写前复核**：用户确认后、写入前再读一次目标单据，核对产品、标题、原始正文是否仍与生成草稿时一致。
   - 不一致 → 停止写入，把当前原文与重新合并后的草稿交给用户确认，不自己合并后继续写。
2. **写**：只发一次更新请求（`bug-update` / `feedback-update`）。
3. **回读**：把回读正文与**完整预期正文**归一化换行后逐字比较（不是看是否包含某几段），并确认 `actions` 里**本次新增**了 `edited`——历史上存在过 `edited` 不算证据。
4. **结果不明**：更新超时或返回无法解析时只读核实，不重放更新；核实不了就报未确认，交回用户。

## 图片上传失败

传图走官方禅道 CLI 的 `file create`（入口脚本 `file-create` 子命令）：`POST {站点}/api.php/v2/files`，`multipart/form-data`，**单文件上限 50 MiB**；`--file` 是**本地路径**，由跑 CLI 的那台机器按**命令执行目录**解析。**上传失败不影响已建好的单据**——单据在传图之前就建好了，报错后不要重发建单请求。

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| 找不到图片文件 / 读不到文件 | 路径不对，或临时文件已被清理（相对路径按命令执行目录解析） | 请用户重新给一次**绝对路径**；不要编造路径 |
| 图片超过上限 | 单文件超过 50 MiB，CLI 直接拦 | 请用户压缩或截图裁剪后重试 |
| `E1004` / `E1003` 一类认证错误 | 令牌或凭据失效 | 按「认证类」处理，先让用户重写凭据 |
| `E2006` 没有权限 | 该账号不能在这类单据上挂附件 | 如实说明权限边界，请用户找管理员开权限 |
| `E2004` / `E2009` 参数无效 | `--object-type` / `--object-id` 写错，或文件类型不被接受 | 换成 `png` / `jpg` 重试一次；仍失败就请用户走禅道网页端上传 |
| `E5001` 超时、`E5003` 取消，或响应看不懂 | **结果不明**：图可能已经传上去了 | 先查单据上有没有多出附件，**不重传**；查不出来就报未确认 |
| 返回里没有文件 ID | 拿不到可引用的文件标识 | 先查禅道里有没有多出附件，别重传 |

上传失败后**不要**做的事：不要把文字描述说成「图已经放上去了」，不要改用 base64 内联绕路（禅道与消费端都不认），也不要为了带图重建一张单据。

## 写后回读：识别静默失败

每次写入后都回读并比对四样东西：

1. `product` 是否是本次写入的产品。
2. `title` 是否与提交一致。
3. 正文是否与**完整预期正文**归一化换行后逐字一致（不是只看包含某几段）。
4. `actions[]` 是否**本次新增**了对应动作：新建应出现 `opened`，改描述应出现 `edited`；历史上有过不算。

对不上就按失败处理，并明确告诉用户「禅道返回成功，但回读发现没有生效」。

缺陷单的比对项对应换成：`product` / `title` / `steps`（**剥掉 HTML 标签并归一化空白**后再逐字比）/ `openedBuild`（`trunk` 与「主干」是同一个值，先归一化）/ `severity` / `pri`，以及 `actions` 里的 `opened`。

## 入口脚本的常见报错

| 报错片段 | 含义 | 处理 |
| --- | --- | --- |
| 读不到载荷文件 | `--payload-file` 路径不对 | 重新写一次载荷文件，用绝对路径 |
| 载荷文件不是合法 JSON：放…不要再套一层 payload | 载荷里套了 `{"payload": {...}}` | 改成请求体本身 |
| 载荷缺必填字段：… | 请求体少了必填项（缺陷单是 `productID` / `title` / `openedBuild`，反馈单是 `product` / `title`） | 补齐后重发；这条请求没被执行，重试安全 |
| 载荷的 product 要写数字 | 产品用了字符串形态（服务端会静默忽略） | 改成整数 |
| 载荷的 … 要写数字 | 该字段用了字符串 | 改成数字 |
| 找不到 zentao 命令 | 官方禅道 CLI 没装，或不在 PATH 里 | 按 [setup.md](setup.md)「Agent 执行路径」装技能包钉住的固定版本，不拿旧脚本顶替 |
| 换禅道令牌失败（HTTP 400）/ 禅道拒绝了本机凭据 | 账号密码不对 | 按「认证类」处理 |
| 禅道 CLI 执行超时 | 超过脚本给 CLI 的超时 | 读命令可重跑；写命令先按「结果不确定」核实 |
| 状态不是已解决或已关闭的 Bug 不能激活。 | 状态机不允许 | 停止该操作，把当前状态说明给用户 |

## 停止条件

出现以下情况，停止自动操作并把决定交回用户：

- 认证连续失败（重写凭据后仍失败）。
- 禅道账号被锁定。
- 两次修正后业务校验仍失败。
- 遇到 `E2010`（这台禅道不支持这个动作）——改用语义等价的做法或交回用户，不硬试。
- 写入后回读不一致且无法判定是否已落库。
- 创建结果无法唯一确认（多条候选，或复查扫描不完整）。
- 补充说明写前复核发现原文已被他人改动：把重新合并后的草稿交回用户确认。
- 用户要求的操作会关闭、删除、解决或转移单据（这些由人来做）。
- 用户要求给缺陷单指派负责人或流转状态（缺陷单也不做）。
- 用户要求的操作超出当前能力（服务端关键词检索、反馈转 Bug；图片只能挂在反馈单与缺陷单上）。
- 用户要提交到当前账号看不见的产品或项目（权限边界，交给人开权限）。

## 禁止的动作

- 不在未确认的情况下跑写子命令（`bug-create` / `feedback-create` / `bug-update` / `feedback-update` / `file-create`）。
- 不在结果不确定时自动重试创建或重放更新。
- 不把写入前就存在的同名单据当成新建成功。
- 不把「没查到」说成「没创建」。
- 不把「保存成功」当成落库证据。
- 不绕过禅道权限限制去达成写入目的。
- 不在回复里输出账号、密码、令牌；汇报连接状态时不贴内网地址（2.7 交付单据链接那次除外）。
- 不在对话里索要禅道密码或令牌，也不把它们写进任何仓库文件。
- 不为了「顺手」退回宿主里那个团队自研的禅道 MCP 工具建单或更新（它的身份是服务端固定账号）。
