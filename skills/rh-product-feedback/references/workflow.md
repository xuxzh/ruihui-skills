# 工作流与话术

示例数据均为虚构。流程主干见 `SKILL.md`，本文给出逐步细节与输出样例。

## 总览

```
用户表达
  │
  ├─ 提交 ──► 登录 ─► 收要素 ─► 草稿 ─► 查重 ─► 确认 ─► 创建 ─► 回读 ─► 交付
  ├─ 查询 ──► 登录 ─► 定位反馈单 ─► 读字段与 actions ─► 三段式解释
  └─ 补充 ──► 登录 ─► 读原文 ─► 追加草稿 ─► 确认 ─► 更新 desc ─► 回读
```

## F1 提交反馈

### 1. 收要素

按 `feedback-templates.md` 判定类型与必填项，一次问全缺失项。

对话样例：

> 要写进禅道还差两项：
> 1. 这是在哪个页面操作时出现的？
> 2. 期望的正确结果是什么？

### 2. 草稿

草稿要展示到用户能逐字判断的程度：

```
类型：Bug
所属产品：示例产品 A（product id: 101）
标题：设备列表导出按钮点击后无响应

描述：
【业务场景】
运维人员在设备管理页导出月度报表。

【复现步骤】
1. 打开「设备管理」
2. 选择时间范围后点「导出」
3. 页面无任何变化，控制台无报错

【实际结果】
点击后无响应，也无失败提示。

【预期结果】
应导出 Excel 文件，或给出明确的失败原因。

【影响范围】
阻断月度报表导出。

【环境】
用户未提供
```

### 3. 查重

调用 `get_products_productID_feedbacks`（`recPerPage=100`，最多 3 页），客户端按标题关键词匹配。

输出样例：

> 在已扫描的 42 条反馈中发现 1 条相近记录：
> - #318「设备列表导出无响应」— 状态 wait — 2026-03-04
>
> 你要：新建一条 / 在 #318 上补充 / 都不合适？

措辞边界：说「在已扫描的 42 条中未发现重复」，不要说「禅道里没有重复」。

### 4. 确认

用户回复「新建」即可视为对当前草稿的明确确认。回复只有「嗯」且尚未展示草稿时，先展示草稿再问一次。

### 5. 创建

```json
{"payload": {"product": 101, "title": "设备列表导出按钮点击后无响应", "desc": "<草稿描述全文>", "type": "bug"}}
```

只发一次。

### 6. 回读

`get_feedbacks_feedbackID`（用返回的 `id`）→ 核对 `title` / `desc` / `status` / `actions`。

```
✓ 创建成功，反馈 #421
状态：wait（待评审）
负责人：未指派
操作流水：opened（2026-03-11 10:22）
```

回读不到或内容不一致 → 见 `error-handling.md`，不要重新创建。

### 7. 交付

```
已提交反馈 #421（示例产品 A）
- 标题：设备列表导出按钮点击后无响应
- 类型：Bug
- 当前状态：wait（待评审），未指派负责人
- 说明：禅道里的提交人显示为共享服务账号，不是你本人的账号
下一步：等评审结果；要补充信息随时说「补充反馈 #421 ...」
```

## F2 查询反馈

### 定位

- 给了编号 → 直接 `get_feedbacks_feedbackID`。
- 给了标题或产品 → `get_products_productID_feedbacks` 分页拉取 + 客户端匹配，列候选让用户选编号。

### 输出格式

```
反馈 #421（示例产品 A）
- 标题：设备列表导出按钮点击后无响应
- 当前状态：wait（待评审）
- 负责人：未指派
- 提交人：共享服务账号
- 处理时间线：
  · 2026-03-11 10:22 服务账号 opened
- 结论字段（result / solution）：空
```

## F3 解释处理进度

三段式，段落之间明确分开：

```
事实
- status = review，说明已进入评审
- actions 最后一条是 2026-03-12 09:40 张工（评审人）review，comment 为空
- reviewedBy = 张工，reviewedDate = 2026-03-12
- plan 与 version 均为空

推断
- 评审动作已发生，但 result / solution 仍为空，推断评审尚未给出结论（推断依据：结论字段为空且评审时间已过）

无法确定
- 没有排期记录的原因——禅道里没有这个字段，也没有评论说明拒绝或延期的理由
```

关键纪律：**没有排期 ≠ 被拒绝**。前者是事实，后者只能是推断，且必须写明是推断。

## F4 补充反馈

### 追加草稿

原文完整保留：

```
<原有 desc 全文>

──────────────
【补充说明 · 2026-03-12 · 用户口述，AI 整理】
【复现步骤补充】
补充：必须先选中至少一行设备，点「导出」才复现；不选直接点没反应。
【预期结果补充】
导出 Excel，文件名格式 yyyyMM设备清单.xlsx
```

### 更新

```json
{"payload": {"product": 101, "title": "设备列表导出按钮点击后无响应", "desc": "<原文 + 追加段>"}}
```

`product` 与 `title` 沿用当前值（禅道要求这两个字段）。

### 回读

核对 `desc` 含追加段，且 `actions` 新增 `edited`。

```
已更新反馈 #421（追加 1 段说明）
- 原文保留，描述从 320 字增加到 512 字
- 操作流水新增：edited（共享服务账号）
```

## 身份边界的措辞

用户问「我提交的全部反馈」时：

> 禅道 MCP 用的是共享服务账号，它看不到具体是谁在对话里。因此「我提交的」我只能按**该服务账号提交的**记录来查；如果你指的是某个具体同事名下的反馈，请告诉我名字，我按人名筛选后再给你。

不要说「这些就是你提交的反馈」，也不要把服务账号的记录说成某个员工的个人工单。
