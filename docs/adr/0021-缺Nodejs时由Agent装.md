# 缺 Node.js 时由 Agent 装，优先用已有的版本管理器

官方禅道 CLI（npm 包 `zentao-cli`）要求 `node >= 18`。Claude Code、Codex 这类宿主的安装包不带 Node.js，机器上不一定有 node——「提醒用户自己去装」会把技能的第一道门槛留给不懂技术的业务用户。

## 决策

1. **Agent 自己装 Node.js，不甩给终端用户**：提示词里写明「先确认这台机器上有 Node.js 18 以上，没有就装一个」，由当前宿主里的 Agent 执行。
2. **优先用机器上已有的版本管理器**（`fnm` / `nvm` / `volta` / `asdf`）：装一个 18+ 的版本，不覆盖任何已有配置。
3. **没有版本管理器才装官方的**：macOS 有 Homebrew 用 `brew install node`；Windows 用 `winget install OpenJS.NodeJS.LTS`；都没有就先装 fnm 再用它。
4. **已有的 node 低于 18 也不动它**（可能是别的项目在用）：在旁边用版本管理器装一个新的，装 CLI 时用那个 node 的 npm。
5. **装完必须让宿主重开**：新装的 Node 不会进已经跑着的宿主进程的 PATH；不重开就会接着报「找不到 zentao 命令」。
6. **装不上才给替代路径**：权限、代理、离线等卡住时如实说明卡在哪一步，并给禅道网页端的自提路径——**不退回用宿主里的禅道 MCP 工具建单**（那是服务端配置的固定身份，单据不会留痕在提交人名下）。

## 后果

- 业务用户的接入门槛回到「发一段话 + 输一次密码」：Node.js 与禅道 CLI 都由 Agent 装。
- Agent 会动用户的机器（装运行时），因此护栏写进技能：**只装不卸、只加不改、优先复用**；已有的 node 一律不动。
- 版本要求仍认官方 CLI 自己的声明（`node >= 18`），技能不另立标准。

## 考虑过的选项

- **只提醒、不代装**（原先的做法）：把门槛留给业务用户，且没给出任何可执行路径——否。
- **直接装系统级 Node、不管有没有版本管理器**：可能顶掉用户已有的 node，或和 fnm/nvm 打架——否。
- **绕开 Node，直接用宿主 MCP 工具**：身份不对（服务端固定账号），单据不留在提交人名下——否（见 [ADR-0017](0017-用官方禅道CLI替换自研接入通道.md)）。
