# 默认负责人可配置，缺省不指派

禅道建缺陷单时若没收到负责人，会把单子指派给**产品的 QD**——实测：MOMV2.0 的 QD 是 `chenqiang`，不传 `assignedTo` 建出来的缺陷单直接挂在他名下（线上缺陷 #1944 就是这么来的，操作流水里有一条 `assigned`，actor 是提交人自己）。也就是说「不指派」在禅道侧不是一个天然结果，而是要显式说出来的。

原先技能只说「不填 `assignedTo`：指派由人决定」，而 `bug-templates.md` 的「字段默认值」表又写着负责人「用默认值」——表里却没有这个默认值。Agent 在这两句话之间自行发挥，就会替用户把单子指派出去；禅道侧的隐式默认更是直接把它挂到 QD 名下，而回读校验原本也不核对负责人。

因此把「默认负责人」做成一个设置，**缺省不指派**：写入脚本在 `bug-create` 时按配置补 `assignedTo`——`""`（不指派）／`qd`（不带这个字段，交给禅道按产品 QD 指派）／具体账号（指给该账号）。配置分两层，与 [ADR-0009](0009-默认产品分两层.md) 同构：随包默认写在 `config.local.json` 的 `bugAssignee`，本机默认写在 `~/.config/rh-zentao/preferences.json` 的 `bugAssignee`，本机优先；终端用户明说（指名或明确不指派）写在载荷里，盖过配置。

## 考虑过的选项

- **只改文档不改代码**（让 Agent 每次显式带 `assignedTo: ""`）：只改一处，但「每次都记得带」是约定不是保证——漏一次，禅道就把单子挂到 QD 名下。
- **不传 `assignedTo`、把默认指派交给禅道**：省掉一个字段，但默认行为变成「自动指派给质量负责人」——那是团队内部缺陷流程的约定，不是提单人的意图。
- **写死成「永远不指派」**：符合当前提单人的诉求，但公司若要沿用「缺陷先到质量负责人」的流程就没有开关。
- **做成可配置项、缺省不指派**（采用）：把禅道侧那个隐式默认变成显式设置，默认值就是提单人想要的「不指派」，要沿用禅道默认或指给固定账号都有开关；代价是多一个配置键和一层解析。
- **随包默认与本机默认分层**（采用）：公司可在 `config.local.json` 预置 `bugAssignee`（例如 `"qd"`），个人在偏好文件里改；与默认产品同一套优先级——用户明说 > 本机 > 随包 > 缺省不指派。

## 后果

- **`config.local.json` 多了一个字段** `bugAssignee`：技能对它是只读的（硬约束 8），只有管理员在仓库里改、随包分发。
- **本机偏好文件多了一个键**：与 `defaultProduct` 同文件，Agent 写设置时合并写，别覆盖已有键。
- **写入脚本多了一点业务判断**：`bug-create` 时按「载荷 > 本机默认 > 随包默认 > 不指派」解析并补字段；反馈单没有这个字段，不受影响。
- **`post_bugs` 的 Schema 里没有 `assignedTo`**：但服务端照收（实测），所以这个开关依赖的是未文档化行为——回读要核对 `assignedTo` 是否与生效值一致。
- **mock 要复刻真实行为**：mock 的 `post_bugs` 现在按产品 QD 自动指派，并在自动指派时记下指派时间与一条 `assigned` 流水；回归测试锁住「不指派」。
