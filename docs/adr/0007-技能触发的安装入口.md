# 技能触发的安装入口：业务用户不再手敲长命令
> 本文的入口形态已由 [ADR-0012](0012-安装与登记交给当前Agent.md) 取代：入口从斜杠命令变成「粘一段安装提示词」，登记与装技能都由当前的 Agent 自己做；本文保留当时的取舍过程。

首次接入多一条**在 Agent 里说一句话**的入口：业务用户输入 `/rh-product-feedback install`（pi 是 `/skill:rh-product-feedback install`），Agent 代跑随包的安装脚本完成「登记禅道 MCP」，凭据仍由本人在自己的终端写入。这条入口取代 [ADR-0006](0006-安装脚本与首次接入.md) 里「用户自己把长命令敲进终端」的主路径，长命令保留为备选。

验收口径：用户从拿到机器到能提第一条反馈，**主动操作 ≤ 4 次**（1 条装技能命令 + 1 句 `/rh-product-feedback install` + 1 条写凭据的命令 + 1 次重启），**全程不需要手写长命令、不需要判断宿主或技能装在哪**。操作次数比 ADR-0006 的 3 次多一次——多出来的那次是写凭据：密码不进对话（ADR-0002 红线）就意味着它必须由本人在自己的终端单独完成。换来的是每次操作都变简单：从「抄一条长路径命令」变成「敲一句斜杠命令」和「粘贴一条 Agent 打印好的命令」。

## 考虑过的选项

- **让 Agent 在对话里索要账号密码、由它代写凭据文件**：能凑成一句话，但凭据会长期留在对话记录里（可能被回放或分享），与 [ADR-0002](0002-业务用户接入形态.md) 的红线冲突。没选。
- **Agent 打开一个终端窗口跑凭据脚本**（macOS `osascript`）：能免掉写凭据那一次操作，但依赖系统自动化授权、失败时没有干净回退、也不是每个宿主都有对应终端。没选；真要做只能作为可选增强，不进主路径。
- **把凭据也自动化**：取决于禅道 MCP 侧的改造（[#7](https://github.com/xuxzh/ruihui-skills/issues/7)），不归这条路径解决。
- **只让用户手敲长命令**（原路径）：要用户自己判断宿主、抄对路径，容易出错；用户反馈「一长串脚本很不方便」。保留为备选，不再是主路径。
- **Agent 代跑安装脚本，用户只写凭据**（采用）：Agent 本来就有命令与文件工具，注册、复核、重启提示都能自动做；只把「必须由人输入的密码」留在人手里。

## 后果

- **Agent 代跑必然发生在宿主运行期间**：这正是 ADR-0006 避开的场景——仓库的判断是运行中的 Claude Code 会回写 `~/.claude.json`，可能覆盖刚登记的条目。因此装得多两道防线：登记完**回读复核**宿主配置里的 `zentao` 条目；重开会话时**自检补登记**（条目不见了就按技能包里的 `config.local.json` 补回，只改这一个键）。无头实测里外部新增的条目会被保留，但没有覆盖到宿主全部写回路径，所以这两道防线不撤。
- **安装脚本不新增开关**：复用已有的 `--skip-credentials`（不代输凭据）与 `--force`（宿主在跑也继续登记）。
- **脚本输出要能直接转交用户**：`--skip-credentials` 时脚本打印写入凭据的那条命令，Agent 原样交给用户，不用自己拼路径。
- **手动路径保留**：技能没被加载、Agent 没有命令工具时，用户仍可自己跑安装脚本；此时仍需先退出 Claude Code（脚本会检测到并停下）。
- **主宿主的体验承诺变了**：不再是「一条命令完成接入」，而是「一句话 + 一条写凭据的命令」。写凭据那一步是可选的（当前禅道 MCP 不校验凭据，Agent 可以先跳过、之后补），但要如实告诉用户「凭据还没写」。
