# 把项目问题纳入技能作为第三种对象

修订 [ADR-0024](0024-放开缺陷与反馈生命周期流转并按操作分级护栏.md) 的「能力范围收口在双对象」与「其余禅道模块另立独立技能」：项目问题（禅道 `issue`）进入 `rh-product-feedback`，与反馈单、缺陷单并列；风险、机会、会议、需求、任务等其余模块仍留在范围之外。

## 背景

- 禅道实例升级到 Max 8.7 后，官方 `zentao-cli` 的 `issue` 资源不再被版本门禁拦下（8.2 上是 `E2010`，整个资源要求 max8.5）。
- 业务上缺陷与问题都要提：缺陷进产品的缺陷单，项目推进中的障碍、需求变更、环境依赖要记到项目的问题台账。
- 技能没有 `issue` 路径时，Agent 会绕开技能直调 `zentao issue`：旧实例上撞 E2010 后改走网页；新实例上无护栏直写——没有查重、确认、回读。

## 决策

1. **第三种对象**：`rh-product-feedback` 的对象从两种扩到三种——反馈单、缺陷单、项目问题。
2. **归属即判据**：缺陷单始终属于产品（项目可选挂），项目问题始终属于项目。用户说「项目 bug」指缺陷单挂到项目下，不建项目问题；描述产品行为出错、带复现步骤 → 缺陷单，围绕项目推进、排期、需求变更、环境依赖 → 项目问题；歧义追问一次并给建议项。
3. **第一版范围**：登记（`issue create`）与查询（`issue get` / `issue list` / 按项目列）。CLI 对 `issue` 没有 update / resolve / close / activate，流转与改字段走禅道网页端，等 CLI 补上再按缺陷单的规则开放；物理删除永不开放。
4. **同一套护栏**：选项目（可见范围、不默认挂）、收要素（`type` 必问、`severity` / `pri` 默认 3、`owner` 当前账号、不指派）、查重（按项目标题）、强制确认（含「不是缺陷单」声明行）、单次写入、按 ID 回读、先查后报。
5. **版本锁不动**：CLI 留在 0.4.4；0.5.0 新增的 max8.5 动作（`bug confirm`、反馈转缺陷 / 需求 / 工单等）另立发版决定。

## 考虑过的选项

- **另立技能**（ADR-0024 原方向）：模块边界干净，但认证与 harness 没有共享机制，另立等于复制接入链路，用户也要记两套入口。等有了共享底座再拆不迟。
- **草稿 + 网页交接**（实例未升级时的过渡方案）：不再需要，升级已落地。
- **单技能全量代理 CLI**：稀释触发精度、撑爆主文档上限，与官方随包技能重叠（ADR-0024 已否）。

## 后果

- 主文档守在 220 行内：路由与边界进主干，细则下沉到参考文档。
- GLOSSARY 新增「项目问题」，「缺陷单」补「项目 bug」的辨析。
- 真实写入验证沿用 ADR-0003 的三道闸门；`issue` 以项目为目标，闸门白名单要补项目维度。
- `feedback get` 在 8.7 上返回 E2006 是升级带来的另一个问题，单独处理，不与本决策混在一起。

## 实施结果（2026-11-26）

- **入口脚本**（`scripts/zentao.mjs`）：新增 `issue-create`（载荷 `objectID` / `title` / `type` / `severity` 必填，`pri` 默认 3，`owner` 为当前账号，`from` 固定 0）、`issues --project <项目ID>`（全量扫描 + 字段投影 + 客户端筛选）、`issue --id <ID>`（一行 JSON）；`dup --kind issue --project <项目ID>` 复用同一套二元组查重与基线。
- **写入护栏**：`issue-create` 只发一次请求，写入前扫目标项目拍基线，写完按 ID 回读核对项目 / 标题 / 类型 / 严重程度 / 描述 / 创建者；结果不确定时只按「基线之外 + 唯一 + 回读一致」核实，不重发。`CREATE_KINDS` 的归属容器从「产品」泛化到「产品 / 项目」。
- **测试**：新增 `tests/zentao-cli-issue.mjs`（13 例：建单、载荷文件、业务失败、回读不一致、缺必填、超时核实、未确认、列表、筛选、详情、查重、非法类型）；`tests/mock-zentao-api.mjs` 的实例版本提到 `max8.7` 并补齐 `issue` 路由；`tests/e2e-live-flow.mjs` 的写入闸门支持项目维度（`ZENTAO_E2E_PROJECT` / `ZENTAO_E2E_ALLOWED_PROJECTS`）。
- **文档**：`SKILL.md` 加「项目问题」路由与「流转 / 改字段不开放」边界（正文 219 行）；`workflow.md` 新增 F1c；`zentao-cli.md` 补 `issue` 命令面与字段；`README.md`、`docs/quick-start.md` 与 `CHANGELOG.md` 同步。
