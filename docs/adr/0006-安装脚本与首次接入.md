# 安装脚本与首次接入：一条命令装好，验收看用户操作次数

> 主路径已由 [ADR-0007](0007-技能触发的安装入口.md) 扩展（多一条「在 Agent 里说 `/rh-product-feedback install`」的入口）；本文的「安装脚本」已由 [ADR-0012](0012-安装与登记交给当前Agent.md) 取代——技能包里不再有安装脚本，装技能与登记 MCP 都交给当前的 Agent。本文保留当时的取舍过程。

首次接入的主路径定为**一条命令**：用户装完技能后跑一次随包的安装脚本，脚本一次完成「装技能 → 登记禅道 MCP → 写入本人禅道账号密码 → 提示重启与验证」，用户重启 Agent 后说「验证一下禅道连接」即完成接入。验收口径：用户从拿到机器到能提第一条反馈，**主动操作 ≤ 3 次**（1 条装技能命令 + 1 条安装脚本 + 1 次重启），全程不手改配置、不手填地址、不在对话里索要密码。

## 考虑过的选项

- **保留「装包 → 对 Agent 说一句 → 跑一条命令」三步**（原方案）：第一要用户自己判断宿主、复制目录、确认装对了，是业务用户最常卡住的地方。
- **在对话里跟用户要账号密码、由 Agent 代写凭据文件**：能凑成一句话，但凭据会进对话记录（会话登录下它本来就要进上下文，但对话记录会长期留存、且可能被回放或分享），与 ADR-0002 的红线冲突。
- **安装脚本一次做完装技能、登记 MCP、写凭据**（采用）：能自动化的全自动化，只把「必须由人输入的凭据」留在人手里；脚本自己从技能包读地址，地址不进对话。
- **让 Agent 在会话里改宿主配置**：运行中的 Claude Code 会回写 `~/.claude.json`，条目可能被覆盖；改为脚本在宿主退出时登记，Agent 只在事后按「只改一个键」复核与修补。

## 后果

- **安装脚本随技能包分发**：`skills/rh-product-feedback/scripts/` 现在带 `install.sh` / `install.ps1` / `set-credentials.sh` / `set-credentials.ps1`。`npx skills add` 装的就是这个目录，所以脚本一定跟着技能到用户机器上——这推翻了「技能目录只放技能本身与接入配置」的旧约定。
- **脚本能重复跑**：已装好的部分跳过，地址一致就什么都不改；登记 MCP 只动 `zentao` 这一个键，保留条目上的其他字段。
- **脚本在 Claude Code 运行时停下**：运行中的 Claude Code 会回写配置，覆盖刚登记的条目；脚本检测到就提示先退出宿主（`--force` 可跳过）。
- **Claude Code 不必为「装技能」重启**：官方文档确认它会热监听 `~/.claude/skills/`，新增技能在当前会话即生效；只有 MCP 配置需要重开。pi 用 `/reload` 即可，两边都不必重启进程来加载技能。
- **凭据默认账号 + 密码**：业务用户不必先去禅道生成令牌；令牌仍支持（`set-credentials.sh --token`）。MCP 改为按用户凭据登录后，凭据已在机器上，直接生效，不用重装。
- **校验结论必须如实**：当前 MCP 恒以服务端固定身份服务，「登录成功」证明不了用户账号可用；验证时要把「凭据已写入」和「当前生效身份是服务端账号」分开说。
- 原 ADR-0004 里「首次接入 ≤4 次交互」的口径被本 ADR 取代；主宿主仍是 Claude Code。
