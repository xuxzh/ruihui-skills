# 每用户独立禅道账号，不用共享服务账号

禅道 MCP 改为由每位业务用户用自己的禅道账号登录，不再使用服务端统一配置的共享服务账号。换来的是反馈单真实留痕在提交人名下、审计可追责、权限按人隔离；代价是每个用户要做一次认证（写入本机接入凭据），且产品、项目、反馈的可见范围因人而异，技能只能在可见范围内操作并如实说明覆盖范围。

## 考虑过的选项

- **共享服务账号**（服务端配好账号，客户端不提交凭据）：接入最省事，但所有反馈都留痕在同一个账号上，审计不出是谁提的。
- **每用户账号 + 客户端提交凭据**（采用）：审计与权限正确，代价是要解决凭据从哪来、怎么不落到对话记录里。
- **每用户账号 + OAuth / SSO 委托登录**：体验最好，凭据永不进 Agent 上下文，但要先让禅道 MCP 支持委托登录。

## 后果

- 禅道权限配置成为接入前提：业务用户看不到的产品，技能不能提交，也不能绕过。
- 登录失败可能触发禅道账号锁定，因此认证失败只重试一次就停。
- 查重范围从「全部反馈」变成「当前账号可见的 N 条」，相关话术已同步修改。
- 反馈的提交人就是用户本人，「我提交的反馈」这类查询可以直接用 `openedbyme` 回答。
