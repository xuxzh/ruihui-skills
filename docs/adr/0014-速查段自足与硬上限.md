# 速查段自足与硬上限：quick-start 的主干只留一处

`docs/quick-start.md` 的「三步速查」从 3 行摘要扩成自足的一段：安装提示词、写凭据的命令、生效与验证、提单示例、提交人提示都在里面，业务用户绝大多数场景只看这一段就够。下面只留例外与边界（换一种装法、提单后会发生什么、常见问题、不归你管的事），接入主干在文档里只有一份。自足靠硬约束维持：速查段 ≤ 40 行、≤ 5 个内容块，`tests/validate-skills.mjs` 每次校验行数、块数与关键锚点。

## 考虑过的选项
- **只压缩措辞、不动结构**：没选。问题不在措辞：能照做的内容本来就在下面第 1/2/3 步里，速查改长了就是同一件事写两遍。
- **速查放满全文**（把整页搬上来）：没选。那等于取消速查，「只看这一段就够」变成「整页都要看」。
- **下面第 1/2/3 步详解原样保留**：没选。主干会出现在两处，迟早对不上——ADR-0013 已经吃过一次同步的亏。
- **全量下沉 `references/setup.md`，quick-start 只留速查**：没选。实施人员要的细节和业务用户要的速查会重新混在一处。
- **提示词只在 `setup.md` 留一份、quick-start 引用它**：没选。速查必须自足，不能要求业务用户先跳进技能包。
- **提示词只在 quick-start 留一份、setup.md 改成指针**：没选，但理由变了。技能包只发布 `skills/rh-product-feedback/`，仓库根的 `docs/quick-start.md` 不随包走（ADR-0013 的同一条理由），只改成指针会让包里的业务用户段指向一个拿不到的文件。改为：quick-start 留读者看的那一份，setup.md 保留随包副本，两处逐字一致由校验脚本断言。
- **不设硬上限、靠评审把关**：没选。文档会被后来的人越写越长，「精简」没有守门人就会失效。

## 后果
- `docs/quick-start.md` 从 131 行降到 103 行，其中「三步速查」39 行；「第 1/2/3 步」「提第一条反馈」「你应该看到什么」「⚠️ 关于提交人」四节删除，内容并入速查或下面的例外章节。
- 安装提示词压缩：去掉「它会按你所在的宿主建好入口」与「其它字段别动」两句冗余，保留必须的四件事（装技能、登记 MCP 只改 `url`、凭据由本人写、给出生效方式）；quick-start 与 setup.md 两处逐字一致，由 `tests/validate-skills.mjs` 断言。
- 「⚠️ 关于提交人」整节删除：一句话进速查，「登录接口不校验凭据」并进常见问题表。
- `tests/validate-skills.mjs` 新增速查段的行数、块数与锚点断言；`GLOSSARY.md` 新增「接入自检」，setup.md 的「只读自检」统一到它。
