# 安装与登记交给当前 Agent：程序不写死宿主清单

> 其中「登记禅道 MCP」这一步已被 [ADR-0017](0017-用官方禅道CLI替换自研接入通道.md) 取代：首次接入不登记禅道 MCP，Agent 装的是官方禅道 CLI。本文保留当时的取舍过程。

首次接入改为**全程在当前 Agent 里完成**：用户把一段安装提示词发给正在用的 Agent，它装技能、登记禅道 MCP、把写凭据的命令交给用户本人执行；技能包里不再有安装脚本，也不再有「Claude Code / pi」这样写死的宿主清单。这条修订 [ADR-0006](0006-安装脚本与首次接入.md)（脚本负责装技能 + 登记 MCP + 写凭据）与 [ADR-0007](0007-技能触发的安装入口.md)（入口是斜杠命令 + 脚本），但保留它们记下的教训：凭据必须由本人输入、登记后必须回读复核、运行中的宿主会回写覆盖条目。

## 考虑过的选项
- **保留安装脚本，给它加宿主识别**（按环境变量或进程祖先认出当前 Agent，只登记给它）：没选。宿主名单仍然要维护——每加一个宿主就得改一次脚本；而「自己是谁、自己的配置在哪」本来就是 Agent 知道的，让程序去猜不如让 Agent 指出来。
- **保留脚本的写死清单，装给所有检测到的宿主**（原行为）：没选。它会在用户没在用的宿主里留下配置，用户也说不清到底装到了哪里，还踩到 ADR-0004 记过的坑（Claude Code 会回写 `~/.claude.json`）。
- **Agent 什么都不用脚本，直接手改宿主配置文件**：没选。登记最终确实落在 Agent 侧，但「从接入配置读地址、合并条目、保留其它字段、写前备份、写后复核」这套动作有现成的通用实现（`zentao-query.mjs sync`），让 Agent 每次现编更容易写坏配置。
- **守住「地址不进对话」**（原约束）：不再坚持。地址随接入配置进公开仓库（[ADR-0005](0005-禅道地址进版本库.md)），本来就不是秘密；为了「地址不能出现在工具调用里」给自己设限没有收益。
- **凭据也交给 Agent 代输**：没选。红线不变——密码不进对话（[ADR-0002](0002-业务用户接入形态.md)）。写凭据仍然是用户在自己终端里跑一条命令，这是整条链里唯一必须由人操作的一步。

## 后果
- 技能包里不再有 `install.sh` / `install.ps1`；只剩 `set-credentials.*`（写凭据）、查询器与上传脚本。内网包的打包脚本与文案同步改。
- 宿主知识从代码搬到文档：`references/setup.md` 的「各宿主配置」给出一张对照表（配置文件路径、条目形状、登记命令、生效方式），Agent 自己判断自己落在哪一行；**新加一个宿主是加一行文档，不是改程序**。
- 登记优先用宿主自己的 MCP 命令（`claude mcp add` / `pi mcp add` / `codex mcp add`），条目已存在且地址不同时才改配置文件，且只改 `zentao` 这一个条目。
- 地址核对（`zentao-query.mjs check` / `sync`）支持 `--config` / `--pointer`，让非 Claude Code / pi 的宿主也能自检；不传参数时仍查内置的两处。
- 安装入口从「一条命令 + 一个斜杠命令」变成「粘一段提示词」：装技能交给 skills CLI（`npx skills add --global`，CLI 自己认宿主并建软链），登记与验证交给 Agent。用户主动操作仍是两次（粘提示词 + 在自己终端写凭据）加一次重载。
- 斜杠命令 `/rh-product-feedback install` 保留：技能装上后它仍触发同一套接入流程。
- 「主宿主 / 次宿主」讲的是**体验承诺**（哪条路径承诺完整闭环），不是「谁会被装」——任何宿主都能由用户直接发起接入。
