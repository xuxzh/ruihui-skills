# 重装用同一段提示词，由 Agent 自己判版本

0.12.0 把接入通道从「随包直连脚本 + 宿主里的禅道 MCP 工具」换成官方禅道 CLI（[ADR-0017](0017-用官方禅道CLI替换自研接入通道.md)）。旧版机器上因此多出三样东西：随包旧脚本（`zentao-client.mjs` / `zentao-query.*` / `zentao-write.mjs` / `zentao-upload.mjs`）、旧参考文档（`references/zentao-mcp.md`）、以及宿主里登记的 `zentao` MCP 条目。业务用户只知道自己「装了个提反馈的技能」，不知道 MCP 与 CLI 的区别，更不该由他们在几种方案里挑。

## 决策

1. **首装与重装用同一段提示词**，由 Agent 自己判断当前是旧版还是最新版：看技能目录里有没有 `scripts/zentao.mjs`（有就是当前通道），没有却有 `scripts/zentao-query.mjs` 或 `references/zentao-mcp.md` 就是旧版。**不问终端用户「你是哪一版」**。
2. **清理由 Agent 做**：作废的旧脚本与旧参考文档由 Agent 删掉。必须删——skills CLI 的更新只覆盖不删除，留着旧文件会让 `skills check` 一直报这个技能「有本地改动」，更新看起来像没生效。
3. **默认删掉旧版登记的 MCP 条目**（Claude Code：`claude mcp remove zentao`；pi：`pi mcp remove zentao`），报告里给一句可撤销的话（「你想自己手动查禅道就说一声」）。这是唯一动宿主配置的地方，且只删这一条旧登记。
4. **接入不重做**：凭据在本机凭据文件里、本机偏好在本机偏好文件里、禅道 CLI 装在系统里，三处都不在技能目录里，重装不动它们——用户最多再输一次密码。
5. **业务用户文档不出现通道术语**：`docs/quick-start.md` 不写 MCP / CLI；版本号 `0.12.0` 只作为通道标记给 Agent 看，判别以文件是否存在为准（0.11.0 既可能是 MCP 版也可能是 CLI 版，光看版本号判不出来）。
6. **备用渠道重发要删旧目录**：内网包 / NAS / 软件中心 / 终端管理没有更新入口，重新分发时必须先删旧技能目录再拷新的。

## 后果

- 用户全程两次输入：发一次提示词、在自己终端里输一次密码。没有版本分支、没有方案选择。
- 提示词只有一份真相：`docs/quick-start.md` 与随包 `references/setup.md` 逐字一致，由 `tests/validate-skills.mjs` 校验。
- 走备用渠道的机器由实施人员重新分发；走 skills.sh 的机器跑一次 `npx skills update` 即可，两条路的差别只在「谁把新文件放到位」。
- 旧版不保留、不做双轨兼容——与 ADR-0017「不并存」一致。

## 考虑过的选项

- **给用户两套提示词（更新用一套、首次安装用一套）**：用户要自己判断自己装的是哪一版，判断错的代价是升级没生效还留着旧脚本。否。
- **让用户在几种升级方案里选**：把技术判断甩给不懂 MCP / CLI 的业务用户。否。
- **保留旧版一段时间做兼容**：两条通道并存时，Agent 与用户都要判断哪条为准，判断错的代价是留痕错误或重复建单（ADR-0017 已否掉同款做法）。否。
