# 业务用户接入形态：Agent 自装 MCP、地址随包分发、凭据由本人写入

> 部分内容已被后续决策取代：地址不再只随内部分发包发出（见 [ADR-0005](0005-禅道地址进版本库.md)），首次接入形态见 [ADR-0006](0006-安装脚本与首次接入.md)。本文保留当时的取舍过程。

禅道 MCP 的地址写死在技能包内的 `config.local.json`（不进仓库，随内部分发包发出），由 Agent 读出后按宿主登记 MCP server；业务用户只需要把技能包放进通用技能目录，然后对自己的 Agent 说一句「帮我连上禅道」。接入凭据由用户自己在终端写入本机凭据文件，Agent 不在对话里索要、也不回显密码。

## 考虑过的选项

- **用户手填 IP 与凭据**（原先的做法）：门槛最高，业务用户最常卡在「IP 是多少」「账号密码放哪」这两步。
- **仓库内置安装脚本**（Node 单脚本，或 bash + PowerShell 两份）：跨平台要维护多份实现，业务用户仍要执行命令，且技能升级路径没有解决。
- **Agent 自装 MCP + 用户自己写凭据**（采用）：跨平台自然（Agent 本来就有文件与命令工具），业务用户只做两件事——说一句话、跑一条命令。

## 后果

- 技能包分两个版本：公开版只有 `config.example.json` 占位符，内网版带真实地址。分发渠道与技能内容解耦，渠道由 IT 现状决定。
- 会话登录模式下，Agent 需要读取凭据文件，令牌会进入 Agent 上下文——因此优先使用可单独撤销的禅道令牌而不是密码。禅道 MCP 若支持 `Authorization: Bearer` 请求头鉴权，可做到凭据完全不进上下文。
- 宿主差异只剩「MCP 配置写在哪」，收敛为 `references/setup.md` 里的适配表。
- 技能在找不到禅道工具或没有凭据时，输出的是可执行的下一步，而不是原始连接错误；这两条路径有模拟层测试覆盖。
