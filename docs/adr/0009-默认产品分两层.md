# 默认产品分两层：随包默认与本机默认

「默认产品」有两种来源：**随包默认产品**写在技能包的 `config.local.json` 里，由分发者预置、随包分发、全公司同一份；**本机默认产品**写在用户自己机器的 `~/.config/rh-zentao/preferences.json` 里，只对本人生效。选品优先级是：用户这次明说的产品 > 本机默认 > 随包默认（**每次使用都要跟用户确认一句**）> 追问一次。

## 考虑过的选项

- **只做随包默认**（全部塞进 `config.local.json`，用时确认）：一处配置，最简单。代价是包更新时会被重写——用户自己设的值会丢；而且预置的产品对看不见它的账号就是无效值，「用时确认」只能挡住误建单，挡不住每次都要多问一句。
- **只做本机默认**（存在用户机器上）：不会被包更新覆盖，也不跨用户泄漏，代价是每个用户第一次都要自己设一次。
- **两层都要**（采用）：公司级默认值由管理员预置一次，大多数人直接用；个人想换产品时说一句「默认产品是 X」写进本机文件，此后直接用，不再问。随包默认不是用户自己选的，所以每次使用都要确认一句。

## 后果

- **`config.local.json` 多了一个字段**：技能对它是**只读**的（硬约束 13：技能包文件不经用户明确要求不改），只有管理员在仓库里改、随包分发；`scripts/build-internal-package.mjs` 会把它带进内网包。
- **本机默认绝不能写进技能包**：那个文件随包分发给所有用户，写进去等于把一个人的产品变成别人的默认值（与 ADR-0005 的分发边界冲突）。
- **选品逻辑多一层判断**：本机默认可直接用；随包默认必须带确认；两者都不可见时如实说明并列出可见产品，不静默换产品建单。
- **用户的确认负担分层**：设过本机默认的用户每次零额外确认；只用随包默认的用户每次多一句确认。
