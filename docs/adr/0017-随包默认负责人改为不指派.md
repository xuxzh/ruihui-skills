# 随包默认负责人改为不指派

[ADR-0016](0016-默认负责人跟产品QD走且可配置.md) 把「默认负责人」做成一个设置，解析顺序 **终端用户明说 > 本机默认 > 随包默认 > 缺省（产品 QD）**，并把**代码兜底**定成产品 QD。那时的判断是「缺省与禅道既有流程一致，承接人必须看得见」，还专门撤回了「缺省不指派」。

现在改的是**随包默认**那一层：技能包 `config.local.json` 的 `bugAssignee` 预置成 `""`（不指派），装了这个包的人建缺陷单时默认不落到任何人名下。**代码兜底不动**——两层都没配时仍按产品 QD 走。

理由是「看得见」那条没兑现。ADR-0016 靠「草稿里具名写 QD 账号、交付时核对 `assignedTo`」让人看见承接人，但看得见不等于没发生：单子一旦落到 QD 名下，禅道就把它算作已指派，认领与改派还得人再动一次；线上也确实出现过缺陷单挂到产品 QD 名下，而 QD 指向谁并不可控（ADR-0016 记的就是 QD 曾指向离职账号）。默认改成不指派，单子停在待认领状态，谁接由人决定——技能不做分配，禅道侧 QD 指向谁也不再影响新单子。

## 考虑过的选项

- **只改随包默认、不动代码兜底**（采用）：公司级的开关本来就是 ADR-0016 留的；两层都没配是几乎不会出现的分支（老版本技能包、没预置该字段的自建包），为它改代码不划算——真要默认不指派，随包预置就够了。ADR-0016 之前那版连**代码兜底**也做成不指派，这次不要。
- **连代码兜底一起改成不指派**：更彻底，但要改 `zentao-write.mjs` 的兜底并重写 `W11` 那条回归测试；收益小，且会让「两层都没配」与「随包预置不指派」两条路径的语义分叉。
- **把随包默认改成指给某个具体账号**：比 QD 可见，但「公司要指定一个默认承接人」是另一件事，没有这次需求。
- **在禅道侧把产品 QD 换成在职的人**：这是 ADR-0016 认定的根因，值得做；但它挡不住「QD 又指向离职账号」再次发生——默认不指派是技能侧自己能守住的那一层。
- **什么都不改，只靠草稿具名提醒**：这是 ADR-0016 的原方案；做不到——草稿具名只是让人看见已经发生的指派，不改变指派本身。

## 后果

- **随包 `config.local.json` 的 `bugAssignee` 是 `""`**：装包的人建缺陷单默认不指派。要恢复 QD 承接，管理员改这一个值；个人可在偏好文件里设 `bugAssignee` 覆盖它。
- **打包脚本要带上这个字段**：此前 `scripts/build-internal-package.mjs` 只写地址与随包默认产品，把 `bugAssignee` 丢了——公司级预置在内网包里根本不生效，随包默认实际退化成代码兜底（产品 QD）。这条一并修掉，并加了回归测试锁住「预置值被带进包里」。
- **草稿与交付的措辞要跟上**：负责人一栏按生效值写——生效值是「不指派」就写「未指派」，是 QD 才具名写 QD 账号；生效值是「不指派」时不必再查 QD。
- **建单后的回读断言变简单**：生效值是「不指派」就断言 `assignedTo` 为空（见 `references/workflow.md`），不再需要拿 QD 账号对照。
