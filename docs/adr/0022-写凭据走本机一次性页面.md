# 写凭据走本机一次性页面，不再把人踢去终端

首次接入的第二步原本是：Agent 把人指向一条命令，人在**自己的终端**跑 `set-credentials.sh` 交互式输入账号密码。红线是密码不进对话（[ADR-0002](0002-业务用户接入形态.md)），而 Agent 的命令环境没有可交互 TTY，代输就会把密码带进聊天记录——于是「一次接入」被拆成两个场所：对话里装好工具，再切到终端写凭据，然后切回来说「验证一下」。

这个断点不在技术难度，在**场所切换**：用户得离开 Agent，从不熟悉的终端里对着一条路径命令操作，失败时的报错还落在终端里，Agent 看不见。

## 决策

1. **首选路径是本机一次性写入页**：随包 `scripts/connect.mjs` 在 `127.0.0.1` 上起一个单页表单，地址带一次性密钥（`http://127.0.0.1:<端口>/k/<32 位十六进制>`），Agent 把地址发给终端用户，用户在自己的浏览器里填账号密码，或粘禅道「个人 → 令牌」生成的个人令牌。
2. **页面自己验证、自己落盘**：提交后先换一次令牌、再用令牌读一次产品列表（都是只读，只发两个请求）；两关都过才写 `~/.config/rh-zentao/credentials`（目录 0700、文件 0600，写临时文件后 rename）。验证不过就不留文件——半截凭据会让下一次会话误判成「已接好」。
3. **红线不变**：凭据只从页面 POST 体进文件，不打印、不落日志、不进命令行参数（`ps`）、不进 Agent 上下文、不进聊天记录。Agent 仍然不索要、不回显。
4. **Agent 只看结果不看凭据**：`connect.mjs start` 打印地址后立刻返回，`wait` 轮询状态文件拿结果（账号、方式、可见产品）；命令超时短也不影响，服务在后台活着，再跑一次 `wait` 就行。
5. **把锁号风险挡在页面上**：连续 3 次验证失败页面自己停手并关掉，用户核对后由 Agent 重开一次；页面 15 分钟过期。
6. **终端脚本保留为兜底**：远程 SSH、没有图形界面、或用户就喜欢终端时仍用 `set-credentials.sh` / `.ps1`（含 `--token`），效果与页面一致。

## 后果

- 用户全程不离开 Agent：装工具、填凭据、自检、提单在同一个对话框里完成，失败信息也回到对话里。
- 技能新增一个本地监听端口与 HTTP 页面（新的攻击面）。护栏：只绑回环、地址带一次性密钥、校验 `Host` 与 `Origin`（别的网页无法跨站提交）、不设 Cookie、不引外部资源（CSP `default-src 'none'`）、写完即退出。
- 页面比终端脚本多了一层「看得见的确认」：用户在页面上直接看到「这个账号能看到哪几个产品」，这正是后续的选品范围。
- 多了一条需要维护的通道（页面 + 终端脚本）。两者写同一个文件、同一套格式，终端脚本仍是唯一的无图形界面路径。

## 考虑过的选项

- **把密码贴进对话，让 Agent 写文件**：最省事，但密码会留在聊天记录与模型服务端日志里，`set-credentials.sh` 的「不代输」底线就此作废——否。
- **Agent 用 `osascript` / `zenity` / PowerShell 弹系统密码框**：不用开浏览器，但要做三套平台实现，部分宿主与远程环境下弹不出来，也看不到验证结果——不作为主路径；页面已经覆盖同样的能力且一套实现跨平台。
- **Agent 驱动浏览器替你登录禅道，再自己建一个个人令牌**：零输入，但依赖宿主自带浏览器工具、要驱动中文 UI、失败时难以解释——否。
- **读浏览器里已有的禅道会话**：要从浏览器凭据库里解出 cookie，需要系统钥匙串授权，且会话过期后还会断——否。
- **把凭据写进宿主环境变量或配置文件**：会跟「凭据只在本机、不进仓库、不进对话」的既有边界打架，重装/换宿主时还会丢——否。
