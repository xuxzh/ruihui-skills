# 快速上手：把 Bug、需求、建议提到禅道

面向**业务用户**。装法是**粘一段话**：把「快速开始」里的提示词发给你正在用的 Agent，之后不用记命令，直接说话就行。

## 快速开始

### ① 接入（三步）

**1. 装技能 + 装禅道工具**：把这段提示词发给你正在用的 Agent（pi、Claude Code、Codex 都行），两件事都在同一个对话框里办完，不用挑、不用配。

```
帮我把 ruihui 的产品反馈助手（rh-product-feedback）装好，已经装过就更新到最新：
1. 技能：来源是 GitHub 公开仓库 https://github.com/xuxzh/ruihui-skills ，装它用 `npx skills add xuxzh/ruihui-skills --skill rh-product-feedback --global`（`npx` 需要 Node.js 18+，没有就先按第 2 条装上）；当前是装好的旧版还是根本没装，你自己判断，不用问我——没装就装这条命令，已经装过但不是最新就跑 `npx skills update rh-product-feedback`；装不上就直说，别从别处找同名技能。
2. 禅道工具：先确认这台机器上有 Node.js 18 以上，没有就装一个（用机器上已有的版本管理器，没有就装官方的），再把技能要求的那个禅道工具装好——版本固定取技能包 `config.local.json` 里 `zentaoCli.version` 的值，不要装最新版；已经装好且版本对得上就跳过。
3. 我的账号密码：给我一个只在我这台机器上打开的一次性页面来填（技能自带的 `scripts/connect.mjs`）——密码只由我本人输入，别替我输、也别让我把密码贴进对话；这台机器上已经写过就不用再写。
4. 收尾：跑一次只读自检，报出我这个账号可见的产品，并说明凭据此刻起有没有生效。
```

**2. 填账号密码（就在 Agent 里，不用开终端）**：Agent 会在你机器上打开一个一次性页面，你在页面上填禅道账号和密码（也可以粘禅道「个人 → 令牌」生成的个人令牌）。密码只填在你自己电脑的浏览器里，**不进对话、也不进命令行历史**；页面当场验证、直接写进本机凭据文件，并告诉你这个账号能看到哪些产品。以 Agent 发给你的那个地址为准；**这一步不能省，也不能交给 Agent 代输**。

**3. 让 Agent 做接入自检**：凭据写好就能用，不用重载。在对话框里说：

> 验证一下禅道连接

它会用你的凭据换一个属于你账号的禅道令牌、读一次产品列表（这份列表就是你能提交到的范围），报出你账号能看到哪些产品，并如实告诉你凭据此刻起有没有生效。

### ② 装好之后：直接说

**照着这几句说**（每句前面那段「用 rh-product-feedback 技能：」别省，Agent 会追问剩下的）：
- 用 rh-product-feedback 技能：设备管理页面点「导出」按钮没反应，帮我提个 Bug。
- 用 rh-product-feedback 技能：希望设备管理支持批量导出 Excel，帮我提个需求。
- 用 rh-product-feedback 技能：每次查询都要重选筛选条件，建议保存上次的筛选条件。

**三件要知道的事**：
- 要 Bug 建的是禅道**正式缺陷单**（进开发流程）；需求与建议建**反馈单**。一次诉求只建一张单。
- 单据上的「提交人」就是你本人——技能用你自己的禅道账号令牌提交；提完会回读核对提交人是不是你。
- Agent 会先给你看草稿、**等你确认**才写进禅道，写完再回读核对；没确认之前不会写。

## 换一种装法

**已经装过这个技能**：在 Agent 里说 `/rh-product-feedback install`（pi 是 `/skill:rh-product-feedback install`），它走的是同一套流程——没装就装，装的是旧版就更新到最新。

**不想让技能常驻、只想试一次**：用 skills CLI 的 `use`（技能落在临时目录），把下面这段发给 Agent：

```
用 `npx skills use xuxzh/ruihui-skills@rh-product-feedback` 拿到这个技能的说明并照着做：把它输出的完整内容先存到临时文件再读；它给的 supporting-files 目录就是技能目录，`SKILL.md` 里的相对路径都从那里解析。然后按其中「0. 接入自检」把技能要求的那个禅道工具装成技能包里钉住的固定版本并校验，再用技能自带的 `scripts/connect.mjs` 起一个只在本机打开的一次性页面让我填账号密码。
```

## 重装 / 更新

技能出了新版本（换了话术、修了 bug），或者你想把它装成最新的样子——**把上面那段提示词原样再发一次就行**，不用换别的说法。Agent 会自己判断你现在装的是哪一版：没装就装、装的是旧的就更新到最新、已经是最新就只做体检。**你不用选，也不用知道版本之间差在哪。**

**重装不用重做接入**：你的禅道账号密码存在你自己机器上（不在技能目录里），禅道工具装在系统里（全局安装，也不在技能目录里），重装都不会动到它们。只要像首次接入那样让宿主重载一次（Claude Code 退出重开，pi 执行 `/reload`），新版本就生效了。

**自己动手也行**：在终端里跑 `npx skills check` 看有没有新版（它会列出所有能更新的技能）；只更新这一个就跑 `npx skills update rh-product-feedback`。

**两件要留意的事**：
- 更新会覆盖技能目录里的文件。你自己改过 `rh-product-feedback` 里的东西（改过 `SKILL.md`、`config.local.json` 或脚本）的话，先备份——`npx skills check` 会把这类改动报成 `has local changes`。
- 如果 `skills update` 找不到这个技能（手动拷过、或锁文件被删），让 Agent 重新装一份：先删掉旧技能目录，再跑 `npx skills add xuxzh/ruihui-skills --skill rh-product-feedback --global`（删掉再装，免得旧版的文件留在里面）。

**别和「换禅道实例」搞混**：禅道地址写在技能包的接入配置里，换地址是管理员改配置再分发一次，跟换新版本是两件事。

## 提单后会发生什么

Agent 会依次做这些事：判断要建哪种单据 → 补齐缺的信息 → 确认属于哪个产品 → 查一下有没有重复的 → 把草稿给你看 → **等你确认** → 写进禅道 → 读回来核对 → 给你单据编号。

**它一定会先给你看草稿、等你确认**。没确认之前不会写进禅道；你说「取消」就一条都不会留。

提交成功后，Agent 会给你这几样：

```
已提交：缺陷单 #1934
产品：设备管理
状态：激活
链接：http://<禅道 Web 地址>/bug-view-1934.html
```

链接是这条单据在禅道 Web 端的直达地址，点开就能看；想自己核对时随时用它。

**要 Bug 建的是禅道「缺陷单」**（正式单据，直接进开发流程，Agent 会在草稿里写明这一点）；**需求与建议建的是禅道「反馈单」**，由人评审后再决定要不要转成正式单据。一次诉求只建一张单，不会同时给你两张。

想核验它是不是真的写进去了，随时问：

> 反馈 421 现在什么状态了？谁在处理？

> 反馈 421 再补充一句：必须先选中至少一行设备才能复现。

## 常见问题

| 你看到的 | 原因 | 怎么办 |
| --- | --- | --- |
| Agent 说没有 rh-product-feedback 这个技能 | 技能目录没放对，或装完没重开 | 问一句「你的技能列表里有没有 rh-product-feedback」确认；装完重开一次 Agent |
| Agent 说「市场里搜不到 / 不知道来源」 | 提示词没带来源，它在别处乱找 | 把「快速开始」里第 ① 步那段提示词**原样重发**——里面带了仓库地址和安装命令 |
| Agent 说找不到 `SKILL.md` | 技能没装到宿主能发现的位置 | 让 Agent 跑 `npx skills add xuxzh/ruihui-skills --skill rh-product-feedback --global`，或把技能包解压到宿主技能目录 |
| Agent 说找不到 `zentao` 命令 | 禅道工具没装，或装包目录不在 PATH 里 | 让 Agent 按技能包接入配置里的固定版本重装一次；装完还找不到，把 `npm prefix -g` 的目录加进 PATH |
| Agent 说没有 node / 装不上工具 | 本机缺 Node.js，或装包被权限、代理挡住 | 让 Agent 给你装上（它会优先用机器上已有的版本管理器）；实在装不上就用禅道网页端提单 |
| 页面填完没生效 | 页面没提交成功，或文件没写成 | 让 Agent 重开一次写入页面（`node <技能目录>/scripts/connect.mjs`）；就喜欢在终端里写的，重跑一次 `set-credentials.sh` |
| 页面打不开 | 你连的是远程服务器，或这台机器没有浏览器 | 让 Agent 改用终端脚本：在你自己的终端里跑 `set-credentials.sh`（Windows 用 `set-credentials.ps1`），效果一样 |
| 登录失败 | 账号或密码不对 | 在页面里核对重填，连续 3 次会自动停手；不要反复试，连续失败可能锁号 |
| 装完 Agent 没反应 | 技能刚装上，宿主还没加载 | Claude Code 退出重开；pi 执行 `/reload` |
| 提交人不是我本人 | 单据不是用你自己的账号提的（旧版经禅道工具建的单会落在公共账号名下） | 让 Agent 用技能自带的入口脚本重提一次——现在建单一定用你自己的账号 |
| Agent 说你的账号看不到某个产品 | 禅道权限没开 | 找管理员开权限，或换一个你有权限的产品 |
| Agent 没给你看草稿就直接报了单号 | 它绕开了技能，自己调禅道接口建的单（没查重、没等你确认） | 到禅道把这条删掉重提；以后提单前面带上「用 rh-product-feedback 技能：」 |
| Agent 一直追问细节 | 缺了它判断分类、复现或验收要用的信息 | 一次答完它问的那几条；确实不知道就说「不知道」，它会写「用户未提供」，不会替你编 |
| 每次都要说产品名 | 还没设默认产品 | 说一句「默认产品是 <产品名>」，它会记在你自己的机器上；也可以让管理员在技能包接入配置里预置一个随包默认产品 |
| Agent 说 `skills update` 找不到这个技能 | 锁条目没了（手动拷过、或锁文件被删） | 让 Agent 重新装一份：先删旧技能目录，再 `npx skills add xuxzh/ruihui-skills --skill rh-product-feedback --global` |
| 重装完 `skills check` 还说有本地差异 | 旧版留下的脚本没删干净 | 让 Agent 按提示把旧版残留的文件清掉 |
| 更新完技能没变化 | 宿主还在用旧版本 | 重载一次：Claude Code 退出重开，pi 执行 `/reload` |

## 不归你管的事

- 关闭、删除、解决反馈单，以及决定单子指派给谁——都由人来做，Agent 只提交内容和读取状态。建缺陷单时默认由产品的质量负责人（QD）承接，它会在草稿里写明承接人是谁；不想让它指派，说一句「默认不指派」即可。
- 截图上传：现在能传了——你把图片粘给 Agent 或给它本机路径，它会把图传到禅道并写进反馈单/缺陷单的正文（禅道的图片必须挂在已存在的单据上，所以它会先建单、再传图、再更新正文）。图传不上去时它会如实说，不会假装传好了。
