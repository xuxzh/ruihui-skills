# 快速上手：把 Bug、需求、建议提到禅道

面向**业务用户**。装法是**粘一段话**：把速查里的提示词发给你正在用的 Agent，之后不用记命令，直接说话就行。

## 三步速查

### ① 接入（三步）

**1. 把这段提示词发给你正在用的 Agent**（pi、Claude Code、Codex 都行）：用哪个 Agent，禅道 MCP 就登记在哪个 Agent 里，不用挑、不用配。

```
帮我装上 ruihui 的产品反馈助手（rh-product-feedback），并接上禅道：
1. 技能没装的话，先运行 `npx skills add xuxzh/ruihui-skills --skill rh-product-feedback --global`，然后读它输出的路径下的 `SKILL.md`。
2. 按这份 `SKILL.md` 的「0. 环境自检」确认能连上禅道：地址在技能包的 `config.local.json`。顺便也把禅道 MCP 登记到**你这个宿主**里（可选，只是让我在对话里也能直接调禅道工具；登记不登记都不影响我提单据）。
3. 告诉我怎么写入我自己的禅道账号密码——密码必须由我在自己的终端里输入，别替我输、也别写进对话。
4. 告诉我怎么让配置生效（重启你，还是执行 `/reload`）。
```

**2. 在你自己的终端写账号密码**：Agent 会把这条命令原样贴给你，复制到自己的终端跑（以 Agent 贴给你的那条为准）；密码不回显，只写在你自己的机器上，**这一步不能省，也不能交给 Agent 代输**——密码进了对话就等于留在了聊天记录里。

```bash
bash ~/.agents/skills/rh-product-feedback/scripts/set-credentials.sh
```

**3. 让配置生效，再验证**：Claude Code 退出重开，pi 执行 `/reload`，其它 Agent 按 Agent 给的提示。生效后，在 Agent 的对话框里说：

> 验证一下禅道连接

它会用你的凭据换一个属于你账号的禅道令牌、读一次产品列表（这份列表就是你能提交到的范围），并如实告诉你凭据此刻起有没有起作用。

### ② 装好之后：直接说

**说这几句就行**（Agent 会追问剩下的）：
- 设备管理页面点「导出」按钮没反应，帮我提个 Bug。
- 希望设备管理支持批量导出 Excel，帮我提个需求。
- 每次查询都要重选筛选条件，建议保存上次的筛选条件。

**三件要知道的事**：
- 要 Bug 建的是禅道**正式缺陷单**（进开发流程）；需求与建议建**反馈单**。一次诉求只建一张单。
- 单据上的「提交人」就是你本人——技能用你自己的禅道账号令牌提交；提完会回读核对提交人是不是你。
- Agent 会先给你看草稿、**等你确认**才写进禅道，写完再回读核对；没确认之前不会写。

**已经装过这个技能**：在 Agent 里说 `/rh-product-feedback install`（pi 是 `/skill:rh-product-feedback install`），它会走同一套接入流程。

**不想让技能常驻、只想试一次**：用 skills CLI 的 `use`（技能落在临时目录），把下面这段发给 Agent：

```
用 `npx skills use xuxzh/ruihui-skills@rh-product-feedback` 拿到这个技能的说明并照着做：把它输出的完整内容先存到临时文件再读；它给的 supporting-files 目录就是技能目录，`SKILL.md` 里的相对路径都从那里解析。然后按其中「0. 环境自检」把禅道 MCP 登记到你这个宿主的配置里，并告诉我怎么写入我自己的账号密码。
```

## 提单后会发生什么

Agent 会依次做这些事：判断要建哪种单据 → 补齐缺的信息 → 确认属于哪个产品 → 查一下有没有重复的 → 把草稿给你看 → **等你确认** → 写进禅道 → 读回来核对 → 给你单据编号。

**它一定会先给你看草稿、等你确认**。没确认之前不会写进禅道；你说「取消」就一条都不会留。

提交成功后，Agent 会给你这几样：

```
已提交：缺陷单 #1934
产品：设备管理
状态：激活
链接：http://<禅道 Web 地址>/bug-view-1934.html
```

链接是这条单据在禅道 Web 端的直达地址，点开就能看；想自己核对时随时用它。

**要 Bug 建的是禅道「缺陷单」**（正式单据，直接进开发流程，Agent 会在草稿里写明这一点）；**需求与建议建的是禅道「反馈单」**，由人评审后再决定要不要转成正式单据。一次诉求只建一张单，不会同时给你两张。

想核验它是不是真的写进去了，随时问：

> 反馈 421 现在什么状态了？谁在处理？

> 反馈 421 再补充一句：必须先选中至少一行设备才能复现。

## 常见问题

| 你看到的 | 原因 | 怎么办 |
| --- | --- | --- |
| Agent 说没有 rh-product-feedback 这个技能 | 技能目录没放对，或装完没重开 | 问一句「你的技能列表里有没有 rh-product-feedback」确认；装完重开一次 Agent |
| Agent 说找不到 `SKILL.md` | 技能没装到宿主能发现的位置 | 让 Agent 跑 `npx skills add xuxzh/ruihui-skills --skill rh-product-feedback --global`，或把技能包解压到宿主技能目录 |
| 登记完了，但重启后连不上 | 运行中的宿主回写覆盖了配置 | 在 Agent 里说「更新禅道地址」，它只改 `zentao` 这一个键 |
| 凭据命令跑完没生效 | 终端里没输完，或文件没写成 | 重跑一次 `set-credentials.sh` |
| 登录失败 | 账号或密码不对 | 核对后重跑凭据脚本；不要反复试，连续失败可能锁号 |
| 用错的密码也提示「登录成功」 | 当前的禅道 MCP 登录接口不校验凭据 | 照常写你自己的账号密码；等 MCP 改成按用户凭据登录后直接生效，不用重装 |
| 装完 Agent 没反应 | 技能刚装上，宿主还没加载 | Claude Code 退出重开；pi 执行 `/reload` |
| 登录成功了，但提交人是另一个人 | 当前 MCP 恒以服务端账号服务 | 别把「提交人」当成自己的名字看；要让人知道是你提的，在描述里写上姓名或工号 |
| Agent 说你的账号看不到某个产品 | 禅道权限没开 | 找管理员开权限，或换一个你有权限的产品 |
| Agent 一直追问细节 | 缺了它判断分类、复现或验收要用的信息 | 一次答完它问的那几条；确实不知道就说「不知道」，它会写「用户未提供」，不会替你编 |
| 每次都要说产品名 | 还没设默认产品 | 说一句「默认产品是 <产品名>」，它会记在你自己的机器上；也可以让管理员在技能包接入配置里预置一个随包默认产品 |

## 不归你管的事

- 关闭、删除、解决反馈单，以及决定单子指派给谁——都由人来做，Agent 只提交内容和读取状态。建缺陷单时默认由产品的质量负责人（QD）承接，它会在草稿里写明承接人是谁；不想让它指派，说一句「默认不指派」即可。
- 截图上传：现在能传了——你把图片粘给 Agent 或给它本机路径，它会把图传到禅道并写进反馈单/缺陷单的正文（禅道的图片必须挂在已存在的单据上，所以它会先建单、再传图、再更新正文）。图传不上去时它会如实说，不会假装传好了。
